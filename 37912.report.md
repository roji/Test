# Issue [#37912](https://github.com/dotnet/efcore/issues/37912): SelectMany from SelectMany with sub-Select fails to translate

## Bug confirmed ✅

The issue is confirmed. When chaining two `SelectMany` calls where the first one wraps the navigation in an anonymous type projection (`.Select(y => new { y })`), EF Core fails to translate the second `SelectMany` which navigates through the anonymous type wrapper.

The first (unwrapped) query succeeds:
```csharp
ctx.Set<E1>().SelectMany(x => x.E2s).SelectMany(x => x.E3s).ToQueryString();
```

The second (wrapped) query fails:
```csharp
ctx.Set<E1>().SelectMany(x => x.E2s.Select(y => new { y })).SelectMany(x => x.y.E3s).ToQueryString();
```

Exception:
```
System.InvalidOperationException: The LINQ expression 'x => x.y.E3s' could not be translated.
```

The stack trace points to `NavigationExpandingExpressionVisitor.ProcessSelectMany`, which fails to recognize the navigation property `E3s` when accessed through the anonymous type wrapper.

## Regression: No

This is **not** a regression. The same error reproduces on:

| EF Core Version | Result |
|-----------------|--------|
| 8.0.24          | ❌ Fails |
| 9.0.13          | ❌ Fails |
| 10.0.3          | ❌ Fails |

This is a long-standing limitation in the query pipeline's navigation expansion logic.

## Provider

Reproduced on SQL Server. The user reports "Any" provider, and since this is a query translation issue in the core `NavigationExpandingExpressionVisitor`, it is provider-independent.

## Possible duplicates

No exact duplicates were found. Related issues:
- [#29185](https://github.com/dotnet/efcore/issues/29185) — VB `SelectMany` failure (different root cause: VB expression tree differences)

## Minimal repro

```csharp
using System;
using System.Collections.Generic;
using System.ComponentModel.DataAnnotations;
using System.Linq;
using Microsoft.EntityFrameworkCore;
using Microsoft.Extensions.Logging;

using var ctx = new MyContext();

var ok = ctx.Set<E1>()
    .SelectMany(x => x.E2s)
    .SelectMany(x => x.E3s)
    .ToQueryString();
Console.WriteLine(ok);

var fail = ctx.Set<E1>()
    .SelectMany(x => x.E2s.Select(y => new { y }))
    .SelectMany(x => x.y.E3s)
    .ToQueryString();
Console.WriteLine(fail);

public class MyContext : DbContext
{
    protected override void OnConfiguring(DbContextOptionsBuilder optionsBuilder)
        => optionsBuilder
            .UseSqlServer("Server=localhost;Database=test;User=SA;Password=Abcd5678;Connect Timeout=60;ConnectRetryCount=0;Encrypt=false")
            .LogTo(Console.WriteLine, LogLevel.Information)
            .EnableSensitiveDataLogging();

    protected override void OnModelCreating(ModelBuilder modelBuilder)
    {
        modelBuilder.Entity<E1>();
        modelBuilder.Entity<E2>().HasOne(x => x.E1).WithMany(x => x.E2s);
        modelBuilder.Entity<E3>().HasOne(x => x.E2).WithMany(x => x.E3s);
    }
}

public class E1
{
    [Key]
    public int Id { get; set; }
    public ICollection<E2> E2s { get; set; }
}

public class E2
{
    [Key]
    public int Id { get; set; }
    public E1 E1 { get; set; }
    public ICollection<E3> E3s { get; set; }
}

public class E3
{
    [Key]
    public int Id { get; set; }
    public E2 E2 { get; set; }
}
```
